# Java 面试学习站

把「读完八股」变成「讲得出来」的 Java 面试学习系统。

## 为什么做这个

现有八股仓库（JavaGuide、advanced-java 之类）的问题不是内容少，而是
**只有「读」这一个动作**：

- **看了 ≠ 会了**。被动阅读没有反馈，合上文章就说不出所以然
- **面试是口头表达**，而所有资料都是书面的。真正的差距是「能不能 60 秒讲清楚」
- **没有追问链**。面试官从来不是问一道题就结束，而是「为什么」→「那如果这样呢」→
  「源码里怎么实现的」，连续追 3~5 层。八股文只给第一层的答案
- **复习没有节奏**，全凭感觉，遗忘曲线没人管

所以这个站点的核心是四件事：
**六段式卡片 + 面试官追问链 + 间隔重复复习 + 自测闭环**。

## 技术栈

| 层 | 选型 |
|---|---|
| 后端 | Spring Boot 3.5.3 / Java 21 / MyBatis-Plus 3.5.17 / MySQL 8.0 / Redis 8 |
| 认证 | JWT 双 token（access 无状态 + refresh 落 Redis 可吊销） |
| 接口文档 | springdoc-openapi 2.8.17（`/swagger-ui.html`） |
| 前端 | Vue 3.5 / Vue Router 5 / Pinia 4 / Element Plus 2.14 / Vite 8 / TypeScript 5.9 |
| 包管理 | 后端 Maven，前端 pnpm |
| 内容源 | Markdown + YAML frontmatter，由导入器解析入库 |

**没有引入 Docker**：直接使用本机已安装的 MySQL 8 与 Redis。

## 快速开始

### 1. 建库

```bash
mysql -uroot -p < backend/src/main/resources/db/schema.sql
```

脚本是幂等的（`CREATE TABLE IF NOT EXISTS`），可以重复执行。

### 2. 起后端

```bash
cd backend && mvn spring-boot:run
```

默认端口 **8081**（8080 常被占用）。数据库连接、JWT 密钥都可用环境变量覆盖：

```bash
JIS_DB_USERNAME=root JIS_DB_PASSWORD=root JIS_JWT_SECRET=<32字节以上> mvn spring-boot:run
```

启动时会自动扫描 `content/` 并导入内容。导入失败**不会阻止应用启动**，
错误会打日志并记入导入结果。

### 3. 起前端

```bash
cd frontend && pnpm install && pnpm dev
```

打开 http://localhost:5173 ，注册一个账号即可。
前端 dev server 把 `/api` 代理到 8081，因此不需要处理跨域。

### 4. 跑测试

```bash
cd backend && mvn test          # 58 个单元测试：FSRS 调度、判分规则、搜索切词、卡片契约
cd frontend && pnpm build       # 类型检查 + 构建
```

## 面试可以讲的工程点

这一节是这个项目最有价值的部分——**每个点都是「问题 → 做法 → 为什么」**，
可以直接当面试素材。

### 1. 内容以 Markdown 为唯一事实源，数据库只负责检索与状态

**问题**：内容放在数据库里，改一个字都要开客户端，没法 review、没法回滚。

**做法**：卡片写在 `content/` 下的 Markdown（YAML frontmatter + 六个固定章节），
由导入器解析后 upsert 进 MySQL。数据库只承担全文索引、知识点关联、
复习状态这些「必须查」的职责。

**为什么**：内容变更有了 git diff；不需要数据库客户端就能审校；
数据库表可以随时重建而不丢内容。所以导入器有一条硬规则——
**只写内容表，绝不触碰 `review_state` / `user_note` / `user_favorite` / `quiz_record`**。

**幂等性**：一切以业务键（模块 slug、卡片 slug、追问 qKey、题目 qKey）做 upsert。
实测连续重复导入，五张表的行数完全不变。

### 2. 按文件隔离失败，但绝不自动删卡片

**问题**：65 个 Markdown 文件里有一个格式写错，整个导入就该失败吗？

**做法**：单个文件解析失败只跳过它并记入 `errors`，其余内容照常导入。
但**数据库里存在、本次未导入的卡片不会被删除**，只在结果里列为警告。

**为什么**：本次导入若有文件报错，那张卡片看起来同样是「未覆盖」。
自动删除会造成内容丢失——这是不可逆的破坏。
宁可留着让用户手动清理，也不能替用户做删除决定。

### 3. 解析器按围栏长度匹配，让挖空题能内嵌代码块

**问题**：挖空题的题干里要放 `java` 代码块，而题干本身被 `yaml` 围栏包裹，
形如 ```` ```yaml ... ```java ... ``` ````。用「遇到三个反引号就闭合」
的简单匹配，内层围栏会把 YAML 提前截断。

**做法**：按 CommonMark 规则实现围栏状态机——**闭合围栏必须与起始围栏
同种字符且不短于它**。因此用四个反引号包裹 YAML 时，内层的三个反引号不会闭合它。

同一个状态机也用于章节切分，避免代码块里以 `##` 开头的注释被误判成新章节。

### 4. 追问链用编号表达层级，并把校验做在导入期

**问题**：追问链是树形结构，人工维护父子关系容易挂错。

**做法**：Markdown 里用 `### Q1:` / `#### Q1.1:` / `##### Q1.1.1:` 表达层级。
导入器强制校验三件事：

1. **标题层级与编号段数一致**（`Q1.1` 必须用 `####`）
2. **父编号必须存在**（写了 `Q2.1` 却没有 `Q2` 就报错）
3. **编号不重复**

**为什么**：这三点覆盖了复制粘贴时的全部典型笔误。与其让脏数据进库、
在页面上表现为「追问莫名其妙跑到别的题下面」，不如在导入期就拒绝。

### 5. 缓存的三个经典问题，各做了一个具体动作

| 问题 | 做法 | 关键细节 |
|---|---|---|
| 穿透 | 空值哨兵（短 TTL） | 必须区分「未命中」与「命中了一个 null 哨兵」，否则查不到的数据每次都打库 |
| 击穿 | Redis 锁串行化回源 | 抢到锁后要**双重检查**；等待超时要**兜底直接回源**（可用性优先于保护数据库） |
| 雪崩 | TTL 加 ±10% 随机抖动 | 避免同一批写入的缓存同时失效 |

**失效策略用版本号而不是遍历删除**：

```
key = jis:cache:v{version}:kp:{slug}
```

内容导入后只做一次 `INCR`，所有旧 key 前缀变了即失效，旧 key 交给 TTL 自然淘汰。
这样一次失效是 O(1)，不需要 `KEYS`/`SCAN` 全库扫描——
`KEYS` 在大实例上会阻塞 Redis，是经典线上事故。

**不用 RedisTemplate 的多态反序列化**：缓存的对象多是 record（final 类型），
多态类型信息根本写不进去，读回来会退化成 `Map`；而且多态反序列化本身是攻击面。
所以显式传 `TypeReference`，类型由调用方确定。

### 6. 中文搜索做成三级检索，精度优先

**问题**：MySQL 的 ngram 全文索引（`ngram_token_size = 2`）在自然语言模式下
是 bigram 或匹配，搜「缓存击穿」会把只提到「缓存」的卡片也带出来。

**做法**：三级降级，逐级放宽：

1. **布尔必需词**：`+缓存 +击穿`，多词之间是「与」语义
2. **自然语言模式**：bigram 或匹配 + 相关度排序，召回更宽
3. **LIKE**：兜底。`ngram_token_size` 默认为 2，单字查询走不了全文索引

**这里最容易踩的坑是：不能把关键词整串交给布尔模式。** ngram 分词会把查询串
切成 bigram 并要求它们连续出现，于是 `+缓存击穿` 等价于「这四个字必须连排」。
标题写作「缓存穿透、击穿、雪崩」的卡片因为中间隔着顿号反而不匹配；恰好有一张
卡片连排出现过该词组，它命中了；而第一级**非空即返回**，第二、三级不再执行——
最该被看到的卡片就这样被挡在结果之外，且没有任何报错。中文用户基本不会打空格，
所以这是常态而非边界情况。

**解法是按 ngram 的粒度切词**：中文切成不重叠的双字词后各自加 `+`
（`缓存击穿` → `+缓存 +击穿`），既保留「两个词都要出现」的精度，又不再要求相邻。
两个细节：末尾剩三字整块保留、剩一字并入上一块，避免产生 ngram 索引命不到的
单字词；ASCII 片段（`HashMap`、`JVM`）整段保留，因为 ngram 解析器把连续的
字母数字当作一个词。标点类片段直接丢弃，用户输入里的 `+ - ~ *` 等布尔操作符
因此天然失效，不需要额外的转义步骤。

实测：搜「缓存击穿」从修复前的 1 条（且不含目标卡片）变为 2 条、目标卡片排第一；
`+垃圾 +回收` 比原来的 `+垃圾回收` 召回更全。

**热搜词按天分桶存 ZSet**，读时合并最近 7 天。不用单个长期 ZSet 是因为
对它续期等于把整个窗口向后滑动，很久以前搜过的词永远不会过期。

### 7. FSRS-6 调度：按官方公式实现，用不变量做测试

**实现**：按官方参考实现移植了遗忘曲线、初始稳定性/难度、难度均值回归、
成功与遗忘两条稳定性更新公式、间隔反解与间隔抖动。21 个参数按语义命名
（`initialStabilityGood`、`recallStabilityDecay`…）并注明对应的 w0~w20。

**两处有意简化，并写在了代码注释里**：
不实现 Anki 那样的多步学习计划（只保留一个 10 分钟的短期重现步长）；
不做个性化参数训练（直接用官方默认参数）。

**测试测的是不变量，不是复刻公式**——算法出错不会抛异常，
只会表现为「复习节奏怪怪的」，所以断言的是：

- 稳定性在成功回忆后单调递增、遗忘后下降
- 四档评分的间隔严格有序
- 难度越高，同样的成功回忆带来的稳定性增幅越小
- **按算出的间隔去复习时，可提取性正好等于目标保留率**（这是间隔反解公式的定义）
- 间隔不超过上限、短间隔不做抖动

跑测试的过程确实纠正了我两处理解错误，都记录在提交信息里：

- 初始难度公式的指数是 `rating - 1`，GOOD 对应 2 而不是 0
- 短期稳定性公式的增幅系数含 `S^-w19`，随稳定性上升而下降；
  对已经很牢固的卡片会低于 1 并被夹到下限，即
  **同日重复复习不增长但也不下降**（这是官方行为，不是缺陷）

**新卡惰性纳入**：导入时**不**给用户批量建 `review_state`
（那是 O(用户数 × 卡片数) 的写放大）。复习队列由「已到期卡片」
加「尚无复习记录的新卡」拼成，新卡有每日配额（默认 10 张），
用户首次评分时才创建状态行。这与 Anki 的新卡/到期卡模型一致。

### 8. JWT 双 token，并且让登出真正生效

**做法**：

- **access token** 无状态、短命（2h），日常请求不查库
- **refresh token** 的 jti 落 Redis，因此**可以真正吊销**；每次刷新都轮换，
  旧的立即失效（防重放）
- **登出**把 access token 按剩余有效期写入 Redis 黑名单，TTL 到期自动清理

**一个真实的坑**：登出接口**必须放行认证拦截器**。

否则 access token 一旦过期，登出请求会被 401 拒绝，
而 refresh token 还会在 Redis 里存活满整个有效期（7 天）——
**用户以为登出了，实际没有**。放行后登出始终可用且幂等，
也没有安全风险：伪造的 token 解析就会失败，登出退化为空操作。

**前端侧配合**：401 自动静默续期，且续期请求做**单飞**
（并发 401 只发一次 refresh）。不做单飞会踩另一个坑——
后端每次刷新都轮换 refresh token，并发的第二个请求会拿着已失效的旧 token
去换，把用户挤下线。

### 9. Redis 锁：解锁必须校验持有者

```java
// setIfAbsent(key, token, ttl) 加锁，token 是 UUID
// 解锁用 Lua 比较 token 再删除
"if redis.call('get', KEYS[1]) == ARGV[1] then return redis.call('del', KEYS[1]) else return 0 end"
```

**为什么不能直接 `DEL`**：A 的业务超时后锁自动过期，B 拿到锁，
此时 A 执行完来删锁，删掉的就是 B 的锁——互斥性被破坏。

**为什么用 UUID 而不是线程 ID**：分布式环境下多个 JVM 的线程 ID 会重复。

**为什么必须用 Lua**：先 `GET` 再 `DEL` 是两次网络往返，中间仍有窗口。
Lua 在 Redis 侧原子执行。

这个锁同时用于保护内容导入任务（避免多实例或重复点击造成并发写冲突）。

### 10. 统一响应体与三级错误码

HTTP 状态码恒为 200，业务结果一律通过响应体的 `code` 表达：

```
0 成功 | 4xx/5xx 对齐 HTTP 语义 | 1xxx 用户与认证 | 2xxx 内容 | 3xxx 复习与答题
```

**为什么**：前端只需在一处拦截器判断 `code`；
认证拦截器也能直接写出结构一致的错误体
（拦截器在 `HandlerAdapter` 之前执行，抛出的异常不会经过
`@RestControllerAdvice`，只能自己写响应）。

### 11. 对外只用业务键，不暴露自增 id

所有内容接口用卡片 `slug`、题目 `qKey` 标识资源，
不暴露 BIGINT 自增 id。两个好处：URL 可读；
**彻底避开 BIGINT 超出 JavaScript 安全整数范围导致的精度丢失**。

需要 id 时在服务层用一个方法换算（`ContentQueryService#findKpId`），
是「外部业务键、内部主键」这条约定的唯一转换点。

### 12. 复习队列与分页的数据一致性

**问题**：按模块过滤复习队列时，如果先查到期记录再过滤模块，
`LIMIT` 会作用在过滤之前，返回的卡片数会不足。

**做法**：用 JOIN 一条 SQL 完成「过滤 + 排序 + 限制」：

```sql
SELECT rs.kp_id FROM review_state rs
JOIN knowledge_point kp ON kp.id = rs.kp_id
WHERE rs.user_id = ? AND rs.due_at <= ?
  AND kp.module_id IN (...)
ORDER BY rs.due_at ASC LIMIT ?
```

同理，**总数与实际返回用同一套过滤条件**，
否则前端会看到「共 30 张待复习」但列表只有 3 张这种对不上的数字。

### 13. 每日统计用原子累加，而不是「先查后改」

```sql
INSERT INTO study_daily (...) VALUES (...) AS new
ON DUPLICATE KEY UPDATE
    review_count = study_daily.review_count + new.review_count, ...
```

用 `INSERT ... ON DUPLICATE KEY UPDATE` 而不是「先查后改」：
后者在并发下会丢计数，而且多一次往返。

两个必须注意的语法细节（都踩过）：

1. 用 MySQL 8.0.19+ 的**行别名**语法（`AS new`）引用待插入值，
   而不是已废弃的 `VALUES()` 函数
2. UPDATE 子句右侧的被加数**必须用表名限定**（`study_daily.review_count`）。
   只写 `review_count` 会让 MySQL 报
   `Column 'review_count' in field list is ambiguous`——
   因为行别名 `new` 也有同名列

### 14. 错题本用「最近一次作答错误」而不是「曾经错过」

**做法**：判断「最近一次」用 `MAX(id)` 而不是 `MAX(answered_at)`：

```sql
WHERE t.user_id = ? AND t.is_correct = 0
  AND t.id = (SELECT MAX(x.id) FROM quiz_record x
              WHERE x.user_id = ? AND x.question_id = t.question_id)
```

**为什么用 `MAX(id)`**：id 自增且单调，不受「同一秒内多次作答
时间戳并列」的影响。

**为什么用「最近一次」**：用「曾经错过」的话错题本只增不减，
很快就没人愿意看了。答对一次就自动移出，这份清单才始终是当下真正薄弱的题。

### 15. 抽题绝不下发答案

判分接口用 `withDetail` 参数控制是否返回 `answer` / `blanks` / `analysisMd`，
这三个字段在抽题时一律为 `null`。

**做法上的选择**：返回 VO 而不是实体。从结构上避免以后有人图省事
直接把实体丢出去——这类「顺手泄漏答案」的问题在代码评审里很难被发现。

### 16. 判分规则的细节

| 题型 | 规则 |
|---|---|
| 单选 / 判断 | 忽略大小写与首尾空白后精确匹配 |
| 多选 | 按字母集合比较，**作答顺序不影响对错**；入库前规范化为字母升序 |
| 挖空 | 逐空比对，可接受多个答案；忽略大小写与首尾空白，并把连续空白折叠成一个空格 |

**挖空题的归一化要拿捏分寸**：写代码时多敲一个空格不该算错，
但也不能宽松到把空白全部删掉——`a b` 和 `ab` 在代码里是两个不同的东西。

**为什么把判分抽成独立的 `QuizGrader`**：它是纯计算，却最容易在细节上出错，
而原先埋在 Service 的私有方法里——没有 Spring 上下文就测不到，错了也不会报错，
只是用户答对却被扣分。抽出来之后 28 个用例直接覆盖这些分支，见下文第 17 节。

### 17. 让内容也有「编译」：复用导入器解析器做全量契约校验

**问题**：卡片是 Markdown，格式错了导入器会报错——但只有真的启动应用、
去看导入日志才会发现。60 多张卡片的格式全靠人工 review 不现实，
而且「追问链层级与编号不一致」这类错误的后果是导入失败或内容挂错父节点。

**做法**：写一个测试，遍历 `content/` 下每个 `.md`，**直接调用导入器用的
`MarkdownCardParser`**，并顺手守住几条质量底线：

| 校验项 | 为什么 |
|---|---|
| 全部卡片能解析 | 格式不符合契约导入就会跳过 |
| `slug` 全局唯一 | 重名会让双链引用指向不确定的卡片 |
| 至少 2 道自测题且非全 `CHOICE` | 全是选择题就退化成背选项 |
| 追问链至少 3 层 | 追问链是本站的核心差异化，浅了与八股清单没区别 |

**关键取舍：复用解析器而不是另写一套规则。** 独立实现迟早会与解析器漂移，
那时会出现「测试通过但导入失败」，比没有测试更误导人。
同理，失败要一次性全列出来而不是遇错即停，否则修一个报一个。

这套校验上线当天就抓到一个真实缺陷（见下表最后一行）。

## 过程中修掉的真实缺陷

这些都是在实测（而不是只看构建通过）时发现的，留在这里作为记录：

| 缺陷 | 根因 |
|---|---|
| 挖空题输入框完全渲染不出来 | 占位符 `{{1}}` 在代码块内，highlight.js 把它切成 `{{` + `<span class="hljs-number">1</span>` + `}}`，渲染后占位符不再连续，正则匹配不到。改为在 Markdown 原文里先换成高亮安全的标记，渲染后再替换 |
| 已作答计数永远不动 | computed 去读 DOM，而 computed 没有响应式依赖会被永久缓存。改为容器上的事件委托写回响应式状态 |
| `Column 'review_count' in field list is ambiguous` | `ON DUPLICATE KEY UPDATE` 右侧被加数没写表名限定，与行别名 `new` 冲突 |
| SQL 语法错误，错误信息里出现字面量 `&gt;=` | 注解里写了 HTML 实体，但该语句未包在 `<script>` 内，MyBatis 不会反转义 |
| 导入时 `Field 'answer' doesn't have a default value` | 挖空题没有 answer，而列是 `NOT NULL` 无默认值，MyBatis-Plus 跳过 null 字段导致插入失败 |
| 登出后 refresh token 仍存活 7 天 | 登出接口走了认证拦截器，access token 过期后无法登出 |
| 移动端无法揭晓复习答案 | 只有键盘快捷键，没有可点击按钮 |
| 评分按钮点击偶发失败 | `transition: all` 配合 hover 位移，指针停在边缘时元素反复进出悬停状态变成移动靶 |
| 响应里的 `dueAt` 与实际入库值不一致 | 响应带纳秒精度，而列是秒精度 |
| 缓存反序列化失败被误判成「数据不存在」 | 未区分「未命中」与「读取失败」，会导致 404 |
| 统计页雷达图完全不渲染 | 容器受 `v-if` 控制，watcher 默认在 DOM 更新**之前**执行（`flush: 'pre'`），ref 为 null 导致初始化提前返回且再无机会。改为 `flush: 'post'`；同一根因还让 `ResizeObserver` 从未挂上 |
| 搜索「缓存击穿」搜不到标题里就带「击穿」的卡片 | 关键词没有空格时整串变成一个 `+` 必需词，ngram 下等价于要求这几个字连续出现。标题「缓存穿透、击穿、雪崩」被顿号断开故不匹配，而一张恰好连排出现过该词组的次要卡片命中了；第一级检索非空即返回，目标卡片就此被挡，且全程无报错。改为按 ngram 粒度切成双字词 |
| 一张卡片的追问链只有 2 层 | 写作时未按契约补到三级，而此前没有任何针对内容的自动化校验，所以一直没被发现。新增的全量卡片契约校验测试上线当天就把它报了出来 |

## 已知限制

诚实地列出来，避免误用：

**内容量**：目前 **61 张卡片 / 509 条追问 / 250 道自测题 / 162 条知识点关联**，
分布在 Java 基础与集合（16）、并发编程（15）、JVM 与调优（11）、
Spring（8）、MySQL（4）、Redis（7）。覆盖集合与 `HashMap`、JMM 与锁、
线程池与并发工具、类加载与 GC、Spring IoC/AOP/事务、MySQL 索引与锁、
Redis 数据结构与缓存三大问题等面试主线。
更细的知识点清单见 [docs/content-backlog.md](docs/content-backlog.md)。

**算法简化**：不实现多步学习计划与个性化参数训练（见上文第 7 节）。

**搜索**：`ngram_token_size = 2`，单字查询退化到 `LIKE`；
中文按双字切词后做必需词匹配（见上文第 6 节），因此「多个词都要出现」
成立，但词序无关——搜「缓存击穿」和「击穿缓存」结果相同。
数据量到十万级时应考虑 Elasticsearch。

**备份的取舍**：导出不包含 `review_log`（只增流水）。另外恢复 `review_state`
时 `create_time` 取导入时刻，而「今日新卡配额」正是按它统计的，
所以导入当天的新卡配额可能被这批记录占满，次日恢复正常。

**未实现**：PWA 离线、AI 模拟面试官（按计划属二期）。

**单机假设**：缓存失效用版本号，多实例部署时依赖 Redis 共享版本号，
这部分是成立的；但定时任务、导入锁没有做多实例协调的完整验证。

**测试覆盖不均**：后端有单测的地方是 FSRS 调度、判分规则、搜索切词、
全量卡片契约；前端没有任何测试框架。导入器的幂等性靠真实导入验证
（连续导入两次比对行数），没有自动化用例；`@SpringBootTest` 级别的
集成测试尚未建立，接口行为目前依赖浏览器实测。

## 内容编写

新增知识点只需在 `content/` 下写一个 Markdown 文件，然后
在「设置 → 重新导入内容」点一下（不必重启后端）。

格式契约见 [docs/content-spec.md](docs/content-spec.md)，
其中包含几个必看的坑：YAML 里值以 `@` 开头要加引号、
值中间出现「冒号 + 空格」会报 `mapping values are not allowed here`、
挖空题的题干内嵌代码块时外层围栏要用四个反引号。

导入器会校验并把错误**带文件名**报出来，不会让脏数据静默进库。
另外 `mvn test` 里的 `ContentCardValidationTest` 会对全量卡片做一次契约校验
（见上文第 17 节），写完新卡片先跑它比启动应用看日志快得多。

## 数据备份

复习进度是这个站点里最不可再生的数据，所以设置页提供导出/导入：

- **导出**：把复习状态、笔记、收藏、答题记录、每日统计导出成一个 JSON，
  关联字段是卡片 slug 与题目 qKey 而不是自增 id，因此换库也能正确恢复
- **导入**：按业务键 upsert，同一份文件重复导入结果一致；
  备份里引用到已删除的卡片/题目时跳过并计入警告，不会整单失败

已知取舍见上文「已知限制」。
